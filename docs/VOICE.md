# 设备麦克风与输入法

第一版通过局域网把 Passport 的麦克风接到电脑已有的语音输入法。
需要本分支的新固件和新版浏览器控制台；旧固件仍能同步用量，但不支持语音。
蓝牙连接继续支持用量和提醒，暂不传输麦克风音频。

## Windows + 讯飞

1. 从 [VB-Audio 官网](https://vb-audio.com/Cable/) 下载 VB-CABLE，解压并以管理员身份运行对应安装程序。官方建议安装后重启电脑。此驱动由第三方提供，遵循其许可。
2. 在讯飞的麦克风设置中选择 **CABLE Output**。如果输入法没有单独选择入口，在系统录音设备中选择它作为默认输入。不要把系统默认扬声器改成虚拟线。
3. 打开 Passport 本机网页，先断开连接，展开“语音输入”。点击“刷新音频设备”，选择 **CABLE Input · Windows WASAPI**，选择讯飞。
4. 开始和结束快捷键预设为 **F6**，请与自己的讯飞设置核对。勾选“启用设备麦克风”，保存并连接。
5. 在设备上长按确认键打开菜单，进入“语音输入”。电脑上先点击目标输入框，再按设备确认键开始说话，再按一次结束。

没有安装虚拟线时，可先选择“仅测试麦克风（不传给输入法）”，保存并连接，使用设备按键检查音量。此模式不输出声音、不触发输入法快捷键。

设备不会自动按回车发送消息。快捷键是输入法现有的全局快捷键，开始前请确认当前输入法和焦点；若 F6 结束的行为与当前版本不符，可修改结束快捷键。
可以取消“自动触发输入法快捷键”，手动在电脑上启动和结束输入法语音，仅用设备传声音排查音频。

## 豆包、Typeless 与 Mac

选择对应输入法后，填写它在本机的开始、结束快捷键。输入法选择只保存配置标签，不会安装或调用任何识别 API。
组合键用 `ctrl+alt+space` 这样的格式；支持 `ctrl`、`alt`、`shift`、`cmd`、空格、字母、数字和 F1–F12。

Mac 安装 [BlackHole 2ch](https://existential.audio/blackhole/)，桥接输出和输入法麦克风都选 BlackHole。
快捷键功能需要系统允许运行桥接的 Python 辅助功能权限。Mac 实机与三款输入法的完整兼容性需分别验证，不应把可选配置当作全部联调通过。

## 行为和排查

- 只有设备确认键可以启动录音；网页启用功能只让麦克风待命。
- 录音时显示音量和时长并保持亮屏，结束后恢复原有自动睡眠策略。
- 单次最多 2 分钟。退出语音页、打开菜单、断连或 2 秒没有收到电脑轮询都会停止采集。
- 录音期间暂时关闭 Wi-Fi 调制解调器省电，结束后恢复原设置，避免省电唤醒延迟造成丢帧。
- 音频以 16 kHz / 16 位 / 单声道 音频经 IMA ADPCM 压缩后通过原有 AES-256-GCM 连接传输。与用量请求共享连接、串行处理，各有独立任务。
- 固件音频队列上限 320 ms，电脑队列上限 500 ms；拥堵时丢弃旧音频，避免积累长延迟。网页显示麦克风状态，桥接状态接口同时提供丢帧计数。
- 这套代码不保存音频文件或识别文本。识别由输入法完成，是否上传云端取决于输入法自己的设置和政策。
- 没有虚拟线时不会自动改用扬声器。安装驱动后若刷新仍找不到，请退出并重新启动后台，再刷新音频设备。

## 验证范围

包含加密请求并发测试、音频包校验、快捷键限制、结束/断连清理测试，以及设备页面与省电状态测试。
运行测试并编译固件不能替代麦克风、虚拟驱动、输入法的端到端实测；硬件联调结果应单独记录。
